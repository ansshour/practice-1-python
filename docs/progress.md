## 1. Подготовили окружение

Для проекта используем Python 3.14.7 и uv 0.12.24. Команда `uv sync --locked` создаёт окружение `.venv` и устанавливает зависимости из `uv.lock`. Создание окружения и установку пакетов выполняет uv, поэтому отдельно запускать pip и virtualenv не требуется.

Версию Python записали в `.python-version`, зависимости проекта — в `pyproject.toml`. Полный набор версий хранится в `uv.lock`, чтобы локальная сборка и GitHub Actions использовали одинаковые пакеты.

## 2. Собрали сайт

Выбрали MkDocs 1.6.1 и тему Material 9.7.7. Для локального просмотра используем `uv run mkdocs serve`, для сборки — `uv run --frozen mkdocs build --strict`. Готовый сайт появляется в `dist/`.

Включили предупреждения о неверных внутренних ссылках и якорях. Строгий режим превращает их в ошибку сборки. Для проверки добавили ссылку на отсутствующую страницу: сборка остановилась, а после исправления прошла успешно.

## 3. Добавили пример научного текста

На [странице с примером](example.md) разместили таблицу и формулу среднего значения. Поиск находит материалы на русском и английском по локальному индексу.

KaTeX, его стили и шрифты включили в сайт. В браузере заблокировали внешние CDN и проверили, что формулы и поиск продолжают работать.

## 4. Настроили GitHub Actions

Сборка запускается при push и pull request. Из ветки `main` сайт публикуется на GitHub Pages через `actions/upload-pages-artifact` и `actions/deploy-pages`. После публикации проверяем ответ HTTP 200 и контрольную строку на странице.

Есть и другой способ: `peaceiris/actions-gh-pages` записывает HTML в ветку `gh-pages`, из которой Pages публикует сайт. Мы выбрали передачу готовой сборки как артефакта, поэтому отдельная ветка с HTML не нужна.

## 5. Настроили Helios

На Helios настроили доставку по SSH/rsync, хранение релизов, preview для веток и ручной откат. Проверили публикацию двух версий, остановку до переключения и возврат предыдущей сборки. Результаты приведены в [P4](p4.md).

При сборке задаём полный адрес сайта в `SITE_URL`: `https://ansshour.github.io/practice-1-python/` для Pages и `https://se.ifmo.ru/~s313344/` для Helios. Для preview добавляется путь тестовой версии. Это нужно, чтобы ссылки и ресурсы открывались и при размещении в подкаталоге.

## 6. Сравнили отечественные сервисы

В [T3](t3.md) изучили GitVerse, SourceCraft и GitFlic, а также три варианта хостинга. Сравнение основано на официальной документации. Из рассмотренных мест размещения практически проверили Helios; сборку в отечественных CI/CD-сервисах не запускали.

## 7. Разобрали ошибку CI и оформили материалы

При первом запуске uv 0.11.19 не смог скачать Python 3.14.7 и сообщил `No interpreter found`. В каталоге загрузок этой версии uv нужного Python не было. После обновления uv до 0.12.24 установка заработала.

Результаты проверок и возникшие ошибки сохранили для отчёта. Отчёт, презентацию и текст доклада храним локально, вне Git. Для кода выбрали лицензию MIT, для авторских текстов — CC BY 4.0.
